# Service Layer webhooks (FP 2602, with FP 2608 additions)

Integration-relevant facts about Service Layer webhooks. Not a general FP 2602 release summary.

## 1. Versions

| Fact | Version | Source |
|---|---|---|
| Webhooks, `EventSubscriptions`, `EventNotifications`, Webhook Messenger Service | 10.0 **FP 2602** | p. 179, `fp2602-change` |
| `BizObjProps` and `FilterExpr` on an event, `ExtDataList` on notifications, the webhook formula language, app-level variables | 10.0 **FP 2608** | p. 191-192, p. 198, p. 200, p. 203 |
| OData v4 metadata annotations and scoped `$metadata` queries (unrelated to webhooks, same revision) | 10.0 FP 2608 | p. 19 |

Do not propose webhooks on an earlier B1 version, and do not use the FP 2608 properties on an FP 2602 system.
Use `/b1s/v2` for all webhook calls; SAP says so explicitly (p. 202).

## 2. Enable, subscribe, deliver

1. **Enable per company** (off by default): `POST CompanyService_UpdateAdminInfo` with
   `{"AdminInfo": {"EnableWebhook": "tYES"}}`. If this fails with `10001237 – Enter valid folder path`, the
   company's `ExcelFolderPath` or `XMLFileFolderPath` do not exist on the Service Layer host; set them to valid
   or empty paths in the same call (p. 179, p. 223-224).
2. **Discover events**: `GET EventSubscriptionsService_GetEventCatalog` lists each business object with its
   `ObjectType` and the transaction types it emits, for example `Orders` (17):
   `Created,Updated,Deleted,Closed,Cancelled,Reopened`; `BusinessPartners` (2) and `Activities` (1007):
   `Created,Updated,Deleted`. UDOs and UDTs are included (p. 180-181).
3. **Subscribe**: `POST EventSubscriptions`. SAP's minimum payload is `WebhookID`, `WebhookURL`,
   `AuthenticationType`, `Handshake` and an `EventCollection` of `BusinessObject` + `TransactionType` (p. 180).
   Manage with `GET`/`PATCH`/`DELETE` and the bound actions `Handshake`, `Pause`, `Resume`, `Replay`
   (`fp2602-change`).
4. **Run the Webhook Messenger Service**, a daemon installed beside Service Layer; default port 40008 for a
   connectivity check (p. 179, p. 203).
5. Events fire whatever created the object: Service Layer, DI API, desktop client or Web Client (p. 180).

## 3. Subscription properties (p. 186-192)

| Property | Rule |
|---|---|
| `WebhookID` | Required, unique per company |
| `WebhookURL` | Required, unique, **must be HTTPS**; the certificate must match the host or IP (SAN) even when verification is off |
| `AuthenticationType` | `None`, `Basic`, `HMAC`, `OAuth`; **default `HMAC`**; anything but `None` needs `AuthenticationCred` |
| `AuthenticationCred` | JSON string: Basic `{Username,Password}`; HMAC `{Key, Algorithm}` with `HMACSha256/384/512`; OAuth `{token_endpoint, client_id, client_secret, grant_type: client_credentials}` |
| `VerifyCertificate` | `tYES` (default) / `tNO`; keep on in production |
| `Handshake` | `tYES` (default) / `tNO`. SAP's quick start sets `tNO`; with `tYES` the receiver must answer a `GET` carrying `X-B1-Webhook-Token` (plus the HMAC signature header when HMAC is used) |
| `State` | `Active`, `Inactive`, `Exceptional` (repeated failures; retries continue, then drops to `Inactive`) |
| `WorkMode` | `Standard` (missed events during downtime are not resent) or `Replay` (manual, via the Replay action) |
| `EventCollection[]` | `BusinessObject` and `TransactionType` must match the catalog. FP 2608: `BizObjProps` (comma-separated **simple** properties added to the payload; complex properties such as document lines are not allowed) and `FilterExpr` (boolean formula over the object's fields, e.g. `DocTotal > 1000`) |

Permission: normal users need **Webhook Manipulation** (permission ID 2249), grantable with
`SBOBobService_SetSystemPermission`; the permission cache refreshes within about a minute (p. 192-193).

## 4. Notification payload (p. 198-200)

An array (batched by default) of event objects in SAP's CloudEvents-style shape: `id`, `specversion`,
`source` (`/default/sap.b1/<CompanyDB>`), `type` (`sap.b1.<BusinessObject>.<Operation>.v1`, e.g.
`sap.b1.Orders.Created.v1`), `subject` (the key, e.g. `"91"`), `time` (UTC ISO 8601), `datacontenttype`,
and `data` holding the key fields plus any `BizObjProps`. FP 2608 also exposes `KeyData`, `DeliveryDetails` and
`ExtDataList` on `EventNotifications` for querying delivery status.

## 5. Company-level configuration (p. 200-202)

Set through `CompanyService_UpdateAdminInfo`, read with `CompanyService_GetAdminInfo`:

| Option | Default |
|---|---|
| `EnableWebhook` | `tNO` |
| `MaxNumberOfWebHooks` | 16 |
| `MessageTTL` (hours) | 24 |
| `WebhookRetryTimes` | 3 |
| `WebhookRetryInterval` (seconds) | 2 |
| `WebhookRequestTimeout` (seconds) | 10 |
| `MessageBatchLimit` | 1024 |
| `MessageRetentionTime` (days) | 30 |

## 6. Delivery semantics (p. 202-203, p. 222-223)

- **Retries** on HTTP 5xx, 408 and 429 and on network failures. **SAP's text is inconsistent on the policy**: the
  configuration table says 3 retries at 2-second intervals (above); the FAQ says up to five retries with
  exponential backoff (2, 4, 8, 16, 32 s). Design for either; do not quote one as settled.
- **Duplicates are possible** after a retry. Receivers must be idempotent, keyed on the event `id`.
- **Ordering** is attempted per company only; one webhook serving several companies gets no ordering guarantee.
- **Deactivation**: URL validation failures (malformed, non-HTTPS, refused, timeout, certificate mismatch or
  untrusted) deactivate the webhook until `Resume`.
- **Replay** resends missed events for one webhook and **pauses delivery to all other webhooks** until it
  finishes; use sparingly.
- Slow endpoints fill an in-memory queue; the messenger waits and batches rather than dropping.

## 7. Integration pattern (practice)

Treat the notification as a signal and fetch authoritative state with a normal Service Layer read, unless
`BizObjProps` (FP 2608) already carries the few fields you need. Make the receiver idempotent, durable (queue
before processing) and quick to acknowledge, because the request timeout is 10 s by default. Terminate TLS
with a certificate the messenger trusts, or import it with the certificate tool in the messenger's `tools`
folder.

## 8. Version guard

For a later feature pack, read the sequential API change log rather than assuming the FP 2602/2608 surface is
unchanged, and confirm the properties above against the client's `/b1s/v2/$metadata`.
